## Methodology

Only WAPI object types reachable through the SDK's `IBObjectManager` interface (typed `Create<Resource>`/`Get<Resource>`/`Update<Resource>`/`Delete<Resource>` methods) are cataloged as managed resources. The full WAPI schema defines several hundred additional object types (grid configuration, member management, RPZ feeds, etc.) that the SDK does not wrap with typed convenience methods — those would require raw `Connector.CreateObject`/`GetObject`/`UpdateObject`/`DeleteObject` calls with hand-built field maps, a materially different implementation shape, and are out of scope.

For each cataloged resource, the **Fields** table lists only the fields exposed through the SDK's Create/Update wrapper methods plus the resource's key response-only fields. Several resources' full WAPI object model (as generated in `objects_generated.go`) expose dozens of additional fields not reachable through any ObjectManager method — these are called out per-resource under **Full Schema Notes** and require the generic Connector to set.

**Immutability** is derived by diffing each resource's `Create<Resource>` method parameter list against its `Update<Resource>` method parameter list: a parameter present in Create but absent from Update means the SDK provides no way to change that value after creation. This replaces the usual Terraform `ForceNew` cross-reference, since the reference Terraform provider does not use `ForceNew` tags anywhere in its schema.

## Non-Standard CRUD Patterns

Resources whose SDK wrapper deviates from the uniform Create/Get/Update/Delete naming and coverage pattern:

- **ExtensibleAttributeDef**: Grid-wide extensible attribute schema (defines the key/type/constraints for the `extattrs`/Ea maps every other resource in this catalog carries). NON-STANDARD CRUD: the ObjectManager wrapper supports Create+Read ONLY — there is no Update or Delete method. Every field is therefore effectively immutable through the wrapper; a controller needing to edit or remove a definition must fall back to the generic Connector (UpdateObject/DeleteObject) with a hand-built field map, the same pattern already required for ZoneAuth updates.
- **FixedAddress**: NON-STANDARD CRUD PATTERN: creation goes through AllocateIP(...), not a Create<Resource>-named method. The controller's Create() implementation must call AllocateIP, not assume a uniform naming convention when generating controller code in Phase 4.
- **ZoneAuth**: NON-STANDARD CRUD: no Update method exists in ObjectManager at all — CRUD is effectively Create+Read+Delete only through the SDK wrapper; any post-creation change (comment, disable, view assignment, NS group, SOA tuning) requires the generic Connector. Live-observed 2026-07-28: GET https://<host>/wapi/v2.9.7/zone_auth returned 4 existing zones in the "Internal" view (peatestinglab.com, example.com, foo.com, bar.com), each with only _ref/fqdn/view populated by default (matches ReturnFields() default).
